================================================================================
INTERVIEW HOUR ARCHITECTURAL DEEP DIVE
================================================================================

Problem: An agent in production loops forever, blows its token budget, and
hallucinates tool calls.

Root Causes:
1. Infinite Loops: Model gets stuck oscillating between two decisions or retrying
   the same failed tool with identical parameters. Without step limits, it runs forever.
2. Token Blowout: Each cycle re-sends the growing conversation history. Without token
   budget guards and compaction, costs explode exponentially.
3. Tool Hallucination: Model invents tool names or schemas not present in registry.
   Without hard validation, runtime either crashes unexpectedly or passes nonsense.

Architectural Remedies Implemented in Day 2:
1. Step & Token Budgets: AgentBudgetGuard enforces maxSteps, maxTokens, and maxCostUsd
   on EVERY iteration. The moment a limit is reached, execution halts deterministically.
2. Tool Layer Input Validation: ToolExecutor validates every tool invocation against
   strict schemas before execution. Any discrepancy generates a structured TOOL_VALIDATION_ERROR
   passed back to the LLM for self-correction.
3. State Persistence & Crash Resume: State is saved to CheckpointStore at every step
   and tool boundary. If a node fails or crashes, runtime.resume(runId) restores the exact
   snapshot without data loss.
4. Deterministic Replay: Every decision and tool output is recorded by ReplayRecorder.
   ReplayEngine can re-run the entire execution trace in milliseconds with zero LLM API costs.
5. Unit Testing Non-Deterministic Agents: Testing agents without live LLMs by:
   - Injecting deterministic decision providers.
   - Recording traces and replaying them under fault injection.
   - Using trajectory assertion suites measuring tool precision, recall, and step efficiency.
